# LoveLab 第一版 UI 设计

日期：2026-10-03。范围：本地可玩的前端体验，用于判断视觉和玩法是否合适。

## 设计参考

查看了以下产品的公开页面与实际视觉：

| 实例 | 参考部分 | LoveLab 的运用 |
| --- | --- | --- |
| [Duolingo](https://www.duolingo.com/) | 轻松的学习氛围、清楚的入门按钮和角色陪伴 | 首页直接试玩，以小狗军师提供简短反馈 |
| [Episode](https://www.episodeinteractive.com/) | 人物插画、故事入口和选择驱动的叙事 | 约会小剧场、对话与选择分列，手机上下排列 |

## 视觉决定

定位为温暖的轻喜剧互动杂志，适合年轻男性通过虚构情景练习表达。视觉变化程度 5/10，动画强度 2/10，信息密度 4/10：有故事氛围，但用克制的布局保持直观。

- 奶油白页面、深绿色主按钮、珊瑚红重点，故事使用桃色、浅绿和淡黄底色。
- 桌面两行大标题，右侧主场景插画；手机变为单列，先看到试玩入口。
- 全站采用同一套圆角、边框和间距变量。弱阴影只用于插画与交互反馈。
- 使用三张 AI 生成的原创插画，涵盖咖啡店、公园和室内倾听。网页图片提供两种分辨率，减少手机传输量。
- Phosphor 图标统一笔画和尺寸。主入口、选项、卡片和弹窗保持统一交互样式。
- 深色模式使用整体主题变量；动态效果尊重系统的减少动态偏好。

## 试玩范围与验收

当前首页引导进入剧场，玩家选择后看到虚构后续和判断理由，再继续下一幕；完成后可以重玩。手册以卡片形式承接剧情中的学习点，收藏回到“我的练习”。

浏览器中已验证三个故事完成流程、今日题、分类筛选、知识搜索与收藏、刷新续玩、完成记录、弹窗焦点、浅深色切换及 390px 手机布局。页面没有发现横向溢出。生产构建通过 TypeScript 检查与 Vite 构建。

性能使用本机生产预览及 Lighthouse 手机模拟检查，分数与指标保存在 `frontend/reports/lighthouse-mobile.json`，属于本机模拟数据，不能代表生产服务器或所有设备。最终结果在本文件末尾记录。

## 后续接入

前端与后端保持独立部署。当前本地数据只用于试玩；后续接入账户、服务端进度、内容版本和管理员发布流程。今日题轮换、不同的剧情结局和大规模内容仍按 PRD 逐步完善。

## 最终性能记录

Lighthouse 12.8.2，生产构建，手机模拟：性能 97，可访问性 100，最佳实践 100，SEO 检查 100。LCP 2.6 秒、CLS 0、TBT 50 毫秒。LCP 略高于 2.5 秒目标，后续上线后需用真实设备与用户监测验证；TBT 不等同于真实用户 INP。上述 SEO 分数仅代表自动检查通过，当前 SPA 未实现服务端渲染。

首页入口 JS 压缩后约 74KB，CSS 压缩后约 7KB；咖啡店手机图片约 61KB。正式环境仍需要静态文件压缩、缓存、图片分发与独立后端压测。
